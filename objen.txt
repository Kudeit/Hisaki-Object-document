Even though `bcd` is an `int`, an assignment like `{bcd} = 'r'` is possible (though it will naturally trigger a warning).
`set x int+char*3 list` allocates 7 contiguous bytes of memory (assuming 4 bytes for `int` and 1 byte for `char`).
`{list+int}` refers to the pointer location offset by 4 bytes (assuming a 4-byte `int`).
Registers specified directly (such as `xl` or `cr3`) are cleared upon `exit` or `went go`. An expression like `{name+1}` refers to a pointer location offset by 1 bit.
Similarly, in the case of `set x int abc` followed by `abc+1`, it refers to a pointer location offset by 1 bit.
`{abc} = 14`
`if <{abc}>`: This condition evaluates to true if the first bit at the `abc` location is 1 (only the first bit is checked). In contrast, `if {abc}` evaluates to true only if the entire `abc` memory area consists of 1s.
`went abc`: This is syntactically valid but causes a crash (because the system attempts to execute code starting at that memory address as if it were an `int` value; a warning is issued). Using `went abc = 15` allows you to skip over the `int` section and jump to the subsequent code (ensure that the following code is properly written after the `abc` definition).
There is no distinction between functions and variables.
When building with `xl`, memory is allocated sequentially according to the C language ABI. This ensures that registers match the C ABI during the initial function call, enabling compatibility with other systems.
`[ ]` denotes a comment.
